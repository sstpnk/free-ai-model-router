# Prompt for TinyLLM Proxy Integration

Use this prompt in the `tinyllm-proxy` project to implement automatic loading of
the config generated by `free-ai-model-router`.

```text
Ты работаешь в локальном проекте C:\Users\Sergey\Code\tinyllm-proxy.

Контекст:
- В проекте free-ai-model-router GitHub Actions генерирует файл output/tinyllm-router-config.yaml.
- Этот файл должен использоваться tinyllm-proxy как динамический слой роутинга.
- Секреты в файле не передаются: только имена переменных окружения вида OPENROUTER_API_KEY.
- Статический config.yaml в tinyllm-proxy остается базовым локальным конфигом для server/auth/admin и ручных настроек.

Сначала прочитай текущие файлы tinyllm-proxy:
- config.yaml
- tinyllm/config.py
- tinyllm/handlers.py
- tinyllm/state.py
- tinyllm/reliability.py
- test_config.py
- README.md, если там описана конфигурация

Формат динамического файла:

metadata:
  schema_version: 1
  generated_by: free-ai-model-router
  generated_at: "2026-09-26T12:00:00+00:00"
  source_output: output/free-router-catalog.json
  route_count: 6
  secrets_policy: api keys are referenced by env var name only
routing:
  cooldown_seconds: 300
  max_attempts: 6
  min_requests_for_trust: 20
  min_success_rate: 0.5
  max_empty_rate: 0.3
  min_score: 0.0
timeouts:
  connect_seconds: 30
  response_seconds: 120
  stream_idle_seconds: 180
providers:
  openrouter:
    type: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key_env: OPENROUTER_API_KEY
    headers:
      HTTP-Referer: https://llm.stpnk.tech
      X-Title: TinyLLM
routes:
  agent-auto:
    - provider: openrouter
      model: poolside/laguna-s-2.1:free
  coding-auto:
    - provider: openrouter
      model: poolside/laguna-s-2.1:free
  agent-auto-pay: []
  coding-auto-pay: []

Задача:
1. Добавь в tinyllm-proxy поддержку опционального динамического конфиг-файла, путь к которому задается через переменную окружения, например TINYLLM_DYNAMIC_CONFIG_PATH. Если переменная не задана, поведение проекта не меняется.
2. Динамический файл может переопределять только sections routing, timeouts, providers, routes. Sections server, auth, admin и другие локальные настройки остаются из базового config.yaml.
3. Реализуй безопасную загрузку:
   - прочитать YAML-кандидат;
   - проверить, что это mapping;
   - проверить schema_version == 1;
   - проверить providers: у каждого есть type=openai-compatible, base_url, api_key_env;
   - проверить routes: каждый route item ссылается на существующего provider;
   - не применять файл, если все routes пустые или отсутствуют;
   - не применять файл, если внутри есть явные секреты: ключ api_key, Bearer-токены, значения с префиксами sk-, gsk_, hf_, csk-, r8_, github_pat_;
   - если max_attempts меньше самой длинной route, либо поднять max_attempts до длины route, либо обрезать route до max_attempts. Выбери более простой и предсказуемый вариант и покрой тестом.
4. Применение должно быть атомарным: сначала собрать и провалидировать новый AppConfig, и только потом заменить активный конфиг. При ошибке оставить старый рабочий конфиг и залогировать причину.
5. Добавь горячую замену:
   - простой polling по mtime файла с интервалом через env TINYLLM_DYNAMIC_CONFIG_POLL_SECONDS, по умолчанию 30 секунд;
   - либо admin endpoint для ручного reload, если это лучше ложится на текущую архитектуру.
   Выбери минимальное изменение, которое хорошо совпадает с текущим кодом.
6. Состояние reliability/cooldown не сбрасывай для provider/model, которые остались в новых routes. Для исчезнувших endpoint можно оставить старую статистику или очистить отдельно, если в текущей архитектуре это проще и безопасно.
7. Обнови README/config documentation: как скачать artifact из free-ai-model-router Actions, куда положить tinyllm-router-config.yaml, какие env vars нужны.
8. Добавь тесты:
   - динамический конфиг применяется и добавляет provider/routes;
   - пустые routes не применяются;
   - неизвестный provider в route отклоняется;
   - inline secret в dynamic YAML отклоняется;
   - невалидный dynamic YAML не ломает старый config;
   - static server/auth/admin остаются из config.yaml;
   - существующие test_config.py проходят.

Проверка:
- python -m unittest discover
- python -m compileall -q tinyllm
- git diff --check

Не меняй free-ai-model-router в этой задаче. Не деплой. Не добавляй реальные API ключи в файлы или тесты.
В финале дай краткую сводку изменений, точные команды проверки и статус git.
```
